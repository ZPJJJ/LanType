# LanType 1.1.2 变更记录（工作稿）

目标版本：`1.1.2 / versionCode 4`，应用 ID `app.lantype.keyboard`。本批仍以手机运行时离线为目标，开发和构建阶段可以联网。

**当前为候选集成与发行准备，尚未完成新 APK 验收。** 本文列出已实施的代码/构建变化和待验证行为，不表示首启问题已经修好或已具备稳定收费发行条件。实际状态见 [1.1.2 验证工作稿](development/lantype-1.1.2-validation.md)。

## 原生兼容性候选

- 独立构建 ORT `1.28.0-r1`，在固定 cpuinfo `4628dc0` 基线上回移 PR 457 的生产 L2 计数/写入防护变更。补丁来源、作者和输入身份单独保留；这是项目选择的生产补丁，不用构建成功推导设备故障已消失。
- [原生构建 44164186969](https://github.com/ZPJJJ/LanType/actions/runs/44164186969) 已成功；新 ARM64 主库为 29,568,744 字节，SHA-256 `ae250081faa6cd742f6edade2a23bf29a96ba690fa19a01e3bd192548cf89f1e`。
- 默认模式接入固定 component 锁的入口已经准备，保留官方 Java classes 和 JNI bridge。最终默认 APK 必须恰好包含 12 个原生库：仅主 ORT 使用新锁身份，其余 11 个仍匹配既有合同。实际整包结果待登记。
- Sherpa JNI 内静态链接的另一份 ORT 未在本批替换或重编。当前变更不能描述为全部原生依赖已经更新。

详细静态结果、AAR 成员比较、源码配置和未验证范围见 [组件说明](licensing/ORT-RUNTIME-1.28.0-r1.md)。

## 构建与来源交付

- 默认整包准备从已公开的 1.1.0 基础运行 ZIP 按锁恢复 **399 个旧输入**，随后执行原生、CameraX 和商业资源校验，避免重复下载旧 NDK/CMake 重编未改的 CameraX。
- 新 ORT 使用独立组件包和 accepted 锁；**组件 ZIP 尚未发布**，公开 URL、外层大小、SHA 和实际验收引用待发行者完成后填入，不提供假锁或 latest 回退。
- 默认预编译与可选 Rime/JNI 源码模式均固定 NDK `29.0.14206865`。独立 ORT 构建器使用 CMake `3.31.6`；该入口不自动签名、发布或接受新库。
- 在 Git 内补入 17 份 NDK 29、Dawn 和补丁归属通知，随本批源码及 APK 提供，并进入当前资源合同；旧 379 个 assets 保留身份。新通知不由旧基础 ZIP 恢复，集成校验状态单独记录。
- 对应来源包含三份基础源码 ZIP、Dawn/WebGPU 补充、项目生产补丁和本次构建器；NDK 29 静态运行时另保留实际输入与来源通知。旧附件、旧标签与旧发行记录不改写。
- 整包 CI 使用受限工作卷和卷外分配量检查点，保留命令 stdout/stderr、退出码、空间观测、APK、完整定向测试及 Compose 渲染。空间不足时停止，不放宽预算完成任务。

命令与材料清单见 [构建和对应源码](LANTYPE-BUILD-AND-SOURCES.md)。
